Problems & Solutions brief

Introduction

SeatLock is a web app for booking cinema and bus seats. Users see the hall or coach live in 3D or on an accessible 2D seat map, pick up to four seats, lock them for five minutes, and get a ticket. An AI seat assistant suggests seats but never books on its own. It is built with React 19, TypeScript, Vite and Three.js.

Aim

To make seat booking fair, clear and recoverable, so that a user always:

  • knows exactly where they will sit before paying,
  • is protected while finishing the booking (seats are locked to them),
  • is told immediately when something changes, and is offered a way forward,
  • can book whatever their device, network speed or accessibility needs.

Problems we found

1. Same seat, same second

Popular seats are taken by several people at once; someone loses after doing all the work.

2. Failed bookings mean starting over

A conflict or error throws the user back to the start with less time and fewer seats.

3. Unclear seat location

A plain grid doesn't show the view, aisle, window or distance from the screen.

4. Slow and unreliable networks

Delays and dropped requests leave users unsure whether the booking went through.

5. Accessibility barriers

Hard to find wheelchair spaces or companion seats, or to book by keyboard or voice.

6. Time pressure and groups

Users race the clock, and friends booking together get split up.

Solutions we are giving

5-minute seat hold

Held seats are locked to the user with a visible countdown; expired holds release seats cleanly.

Conflict recovery (AutoRescue)

If a seat is taken first, other seats are kept and the nearest similar seat is offered in one tap.

3D + 2D seat views

Live 3D hall and coach, a "view from seat" camera, and five clear seat states (colour + icon).

Live, honest feedback

Availability refreshes every 2.5 s; lost seats are flagged at once; failures get a clear message instead of silence.

Accessible by design

Keyboard seat grid, screen-reader announcements, 44 px touch targets, voice in English and Hindi.

Fair and group-friendly

Max 4 seats per booking, buddy seating for groups, and an AI assistant that suggests but never books.

Prototype: bookings run on a simulated organizer API with realistic delays and failures; payment is a demo confirmation. Repo: github.com/Gaurav-7489/-hackathon-byteforce
